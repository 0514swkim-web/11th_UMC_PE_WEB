## 1. 웹이 화면에 뜨기까지

### 용어
| 용어 | 쉬운 설명 | 비유 |
|---|---|---|
| **인터넷** | 전 세계 컴퓨터를 잇는 연결망 | 도로망 |
| **웹(Web)** | 인터넷 위에서 주소로 문서를 주고받는 서비스. 인터넷 ≠ 웹 | 도로 위를 다니는 택배 서비스 |
| **브라우저** | 웹 페이지를 요청하고, 받은 파일을 해석해서 화면에 그리는 프로그램 (Chrome, Edge, Safari) | 택배를 받아서 조립해주는 사람 |
| **클라이언트** | 무언가를 **요청하는 쪽**. 웹에서는 보통 브라우저 | 주문하는 손님 |
| **서버** | 요청을 받고 **응답하는 쪽** | 주문을 받는 가게 |
| **URL** | 웹에서 페이지나 파일의 위치를 나타내는 주소 | 가게 주소 |

> 클라이언트와 서버는 **기계 종류가 아니라 역할 이름**이다. 같은 컴퓨터라도 요청하면 클라이언트, 응답하면 서버다.

### 흐름
```
주소 입력 → 서버에 파일 요청 → HTML·CSS·JS 응답 → 브라우저가 해석 → 화면 표시
```

### 세 기술의 역할
| 기술 | 담당 | 집으로 치면 | 예시 |
|---|---|---|---|
| **HTML** | 구조와 의미 | 방과 가구 배치 | 제목, 문단, 버튼 |
| **CSS** | 모양과 배치 | 벽지, 인테리어 | 색, 크기, 여백, 정렬 |
| **JavaScript** | 동작 | 전등 스위치, 자동문 | 클릭하면 글자 바꾸기 |

순서도 이대로 생각하면 쉽다: **HTML로 뼈대 → CSS로 꾸미기 → JS로 움직이기**.

## 2. HTML: 무엇이 있는지

**HTML**은 **마크업 언어**다. "마크업"은 내용에 표시(태그)를 붙여서 "이건 제목이야, 이건 문단이야" 하고 역할을 알려준다는 뜻이다. 계산이나 판단은 못 한다.

### 태그, 요소, 속성
```html
<a href="https://developer.mozilla.org/">MDN 방문하기</a>
```
| 용어 | 위 예시에서 | 쉬운 설명 |
|---|---|---|
| **태그(tag)** | `<a>`, `</a>` | 시작과 끝을 표시하는 꺾쇠 기호. 여는 태그와 닫는 태그(`/`)가 짝 |
| **요소(element)** | 줄 전체 | 여는 태그 + 내용 + 닫는 태그를 합친 한 덩어리 |
| **속성(attribute)** | `href="..."` | 요소에 붙이는 추가 정보. `이름="값"` 형태 |
| **중첩** | `<ul>` 안의 `<li>` | 요소 안에 요소를 넣는 것. 상자 안의 상자 |

`<img>`, `<input>`처럼 **닫는 태그가 없는 요소**도 있다. 안에 넣을 내용이 없기 때문이다.

### 문서 기본 골격
```html
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>나의 첫 웹 페이지</title>
  </head>
  <body>
    <h1>안녕하세요!</h1>
    <p>웹 개발을 시작합니다.</p>
  </body>
</html>
```
| 부분 | 역할 |
|---|---|
| `<!doctype html>` | "최신 HTML 문서야"라고 브라우저에 알림 |
| `<html lang="ko">` | 문서 전체를 감싸는 맨 바깥 요소. 주 언어는 한국어 |
| `<head>` | **화면에 안 보이는** 문서 정보 (탭 제목, 글자 인코딩) |
| `<meta charset="UTF-8">` | 한글이 깨지지 않게 문자 인코딩 지정 |
| `<meta name="viewport">` | 휴대폰에서도 화면 너비를 제대로 계산하게 함 |
| `<body>` | **실제로 화면에 보이는** 내용 |

> VS Code에서 빈 `.html` 파일에 `!` 입력 후 Enter를 누르면 이 골격이 자동으로 생긴다.

### 자주 쓰는 태그
| 태그 | 역할 |
|---|---|
| `<h1>` ~ `<h6>` | 제목. 숫자가 작을수록 중요 (`h1`이 가장 큰 제목) |
| `<p>` | 문단 (paragraph) |
| `<a href="">` | 링크 (anchor) |
| `<img src="" alt="">` | 이미지. `src`는 이미지 주소, `alt`는 대체 설명 |
| `<ul>` + `<li>` | 순서 없는 목록 + 목록의 각 항목 |
| `<button>` | 누르면 동작하는 버튼 |
| `<label>` + `<input>` | 입력창과 그 설명. `label`의 `for`와 `input`의 `id`를 같게 맞추면 연결됨 |

### 시맨틱 HTML
**시맨틱(semantic)** = "의미의". 시맨틱 태그는 **이름만 봐도 역할을 알 수 있는 태그**다.

> 비유: 서랍에 "양말", "속옷" 라벨을 붙여두는 것. 모든 서랍을 그냥 "서랍"(`<div>`)이라고 부르면 열어봐야 안다.

| 태그 | 역할 |
|---|---|
| `<header>` | 페이지나 구역의 머리말 |
| `<nav>` | 주요 메뉴 링크 묶음 (navigation) |
| `<main>` | 페이지의 핵심 내용. **페이지에 하나만** |
| `<section>` | 한 주제로 묶인 구역. 제목을 같이 두는 게 좋음 |
| `<article>` | 따로 떼어도 읽을 수 있는 독립 콘텐츠 (블로그 글 한 편) |
| `<aside>` | 본문과 관련 있지만 빠져도 되는 보조 내용 (관련 링크) |
| `<footer>` | 마무리 정보 (연락처, 저작권) |
| `<div>` | 의미 없는 그냥 상자. 맞는 태그가 없거나 배치용 묶음이 필요할 때 사용 (틀린 태그 아님) |

**왜 쓰나?**
- **웹 접근성**: 장애가 있거나 어떤 기기를 쓰든 누구나 웹을 쓸 수 있게 만드는 것. 화면을 못 보는 사람은 **스크린 리더**(화면 글자를 소리로 읽어주는 프로그램)를 쓰는데, `<main>`, `<nav>`가 있으면 원하는 구역으로 바로 건너뛸 수 있다.
- **읽기 쉬운 코드**: `<div class="nav">`보다 `<nav>`가 역할을 바로 알려준다.
- 선택 기준은 **모양이 아니라 역할**이다.

## 3. CSS: 어떻게 보이는지

**CSS**는 **스타일시트 언어**다. HTML 요소의 색, 크기, 배치를 정한다.

### CSS 규칙의 구조
```css
h1 {
  color: #2563eb;
  font-size: 32px;
}
```
| 용어 | 위 예시에서 | 쉬운 설명 |
|---|---|---|
| **선택자(selector)** | `h1` | 꾸밀 요소를 **고르는** 부분 |
| **속성(property)** | `color` | **무엇을** 바꿀지 |
| **값(value)** | `#2563eb` | **어떻게** 바꿀지 |
| **선언(declaration)** | `color: #2563eb;` | 속성 + 값 한 줄 |
| **규칙(rule)** | 블록 전체 | 선택자 + 선언 묶음 |

> `#2563eb`는 색을 16진수로 쓴 것이다. 앞 두 자리가 빨강, 중간이 초록, 끝이 파랑의 양.

### 기본 선택자
| 선택자 | 쓰는 법 | 고르는 대상 | 비유 |
|---|---|---|---|
| 태그 | `h1` | 그 태그 전부 | "학생 전원" |
| 클래스 | `.description` | `class="description"`인 요소들 (여러 개 가능) | "3반 학생들" |
| 아이디 | `#page-title` | `id="page-title"`인 요소 **하나** | "학번 2024001번" |

같은 스타일을 여러 곳에 쓸 때는 **클래스**를 쓰는 게 기본이다.

### 스타일이 겹치면? (캐스케이드와 명시도)
- **캐스케이드(cascade)**: 한 요소에 여러 규칙이 겹칠 때 최종 값을 정하는 브라우저의 규칙. "폭포처럼 위에서 아래로 흘러내려 덮어쓴다"는 뜻.
- **명시도(specificity)**: 선택자마다 매겨진 우선순위 점수. **아이디 > 클래스 > 태그** 순으로 세다.
- 점수가 같으면 **나중에 쓴 규칙**이 이긴다.
- `!important`는 순위를 강제로 1등으로 만드는 도장이다. 문제를 덮는 용도로 습관적으로 쓰지 않는다.

### 박스 모델
브라우저에서 모든 요소는 **사각형 상자**다.

> 비유: 택배 상자

```
┌──────────── margin (다른 상자와의 거리) ────────────┐
│  ┌───────── border (상자 벽) ─────────┐             │
│  │  ┌────── padding (뽁뽁이) ──────┐  │             │
│  │  │        content (물건)        │  │             │
│  │  └──────────────────────────────┘  │             │
│  └────────────────────────────────────┘             │
└─────────────────────────────────────────────────────┘
```
| 영역 | 설명 |
|---|---|
| `content` | 실제 내용(글자, 이미지)이 들어가는 곳 |
| `padding` | 내용과 테두리 사이 **안쪽** 여백 |
| `border` | 테두리. `border-radius`로 모서리를 둥글게 |
| `margin` | 테두리 **바깥쪽** 여백. 이웃 요소와의 거리 |

**`box-sizing: border-box`**
- 없으면: `width: 300px` + `padding: 20px`(양쪽) + `border: 1px`(양쪽) → 실제 가로 **342px**
- 있으면: padding과 border를 300px **안에 포함** → 실제 가로 **300px**
- 요소가 생각보다 크면 padding과 border부터 의심하자.

### display: 줄을 어떻게 차지하나
| 값 | 동작 | 예시 태그 |
|---|---|---|
| `block` | 한 줄을 통째로 차지, 위아래로 쌓임 | `div`, `p`, `h1` |
| `inline` | 내용 크기만큼만, 옆으로 나란히 | `a`, `span` |
| `flex` | 자식들을 한 방향으로 줄 세움 | 직접 지정 |

### Flexbox
여러 요소를 **가로 또는 세로 한 줄로 정렬**하는 방법이다. 부모에게 `display: flex`를 주면 자식들이 줄을 선다.

> 비유: 선생님(부모)이 "한 줄로 서!" 하면 학생들(자식)이 줄 서는 것

| 속성 | 하는 일 |
|---|---|
| `display: flex` | 자식들을 한 줄로 세움 (기본은 가로) |
| `gap` | 자식 사이 간격 |
| **주축** | 줄이 늘어서는 방향 (기본 가로) |
| **교차축** | 주축과 수직인 방향 (기본 세로) |
| `justify-content` | **주축** 정렬 (`center`면 가로 가운데) |
| `align-items` | **교차축** 정렬 (`center`면 세로 가운데) |
| `flex-wrap: wrap` | 자리가 모자라면 다음 줄로 넘김 |

연습: [Flexbox Froggy](https://flexboxfroggy.com/#ko)

### 가상 클래스와 반응형
- **`:hover`**: 마우스를 올린 **상태**를 고르는 선택자. 휴대폰엔 마우스가 없으니 중요한 기능을 hover에만 두지 않는다.
- **반응형 디자인**: 화면 크기에 맞춰 모양이 바뀌게 만드는 것.
- **미디어 쿼리**: "화면이 이 조건일 때만 이 CSS 적용" 규칙.
```css
.card {
  width: 90%;          /* 화면의 90% */
  max-width: 560px;    /* 그래도 560px보다는 커지지 않게 */
  margin: 40px auto;   /* 좌우 auto = 가운데 정렬 */
}

@media (max-width: 480px) {   /* 화면 너비 480px 이하일 때만 */
  .card { padding: 20px; }
}
```

## 4. JavaScript: 누르면 무엇이 바뀌는지

**JavaScript(JS)**는 **프로그래밍 언어**다. HTML·CSS와 달리 계산하고, 조건을 따지고, 사용자 행동에 반응할 수 있다.

### 값, 변수, 자료형
| 용어 | 쉬운 설명 | 예시 |
|---|---|---|
| **값** | 프로그램이 다루는 데이터 그 자체 | `"광수"`, `1`, `true` |
| **변수** | 값에 붙인 이름표. 나중에 이름으로 꺼내 씀 | `const name = "광수";` |
| **선언** | 변수를 새로 만드는 것 | `const`, `let` |
| **할당** | 변수에 값을 넣는 것 (`=`) | `level = 1;` |
| **자료형** | 값의 종류 | 아래 표 |

| 자료형 | 뜻 | 예시 |
|---|---|---|
| 문자열(string) | 글자. 따옴표로 감쌈 | `"HTML"` |
| 숫자(number) | 숫자 | `0`, `3.14` |
| 불리언(boolean) | 참/거짓 둘 중 하나 | `true`, `false` |
| `null` | "일부러 비워둠" | `const empty = null;` |
| `undefined` | "아직 아무것도 안 넣음" | `let notAssigned;` |

위 다섯 개는 **원시 값**(더 쪼갤 수 없는 기본 값)이다. 배열, 객체, 함수는 **객체** 쪽에 속한다.

**`const` vs `let`**
| | `const` | `let` |
|---|---|---|
| 다시 할당 | ❌ | ⭕ |
| 언제 | **기본값**. 특별한 이유 없으면 이거 | 나중에 값을 바꿔야 할 때만 |

> 이름은 `data`, `value`보다 `studentName`, `currentLevel`처럼 **무엇이 들었는지 보이게** 짓는다.

### 배열과 객체
```js
const skills = ["HTML", "CSS", "JavaScript"];   // 배열
const student = { name: "광수", level: 0 };     // 객체

skills[0];      // "HTML"  ← 첫 번째는 0번
student.name;   // "광수"
```
| 용어 | 쉬운 설명 | 비유 |
|---|---|---|
| **배열(array)** | 순서대로 줄 세운 값 목록 | 번호표 붙은 사물함 줄 |
| **인덱스(index)** | 배열 안 위치 번호. **0부터** 시작 | 사물함 번호 |
| **객체(object)** | 관련 값을 `이름: 값`으로 묶은 것 | 이름표 붙은 서랍장 |
| **프로퍼티(property)** | 객체 안의 `이름: 값` 한 쌍 | 서랍 하나 |

**`const`인데 배열에 `push`가 되는 이유**
- 배열·객체 변수에는 내용물이 아니라 **참조**(그 내용물이 있는 위치)가 들어 있다.
- `const`가 막는 건 "다른 위치로 바꿔치기"이지 "안의 내용 수정"이 아니다.
```js
const skills = ["HTML"];
skills.push("CSS");   // ⭕ 안에 추가
skills = ["React"];   // ❌ 다른 배열로 바꿔치기
```
> 비유: `const`는 "이 사물함만 쓸 것"이라는 규칙. 사물함 안 물건은 넣고 빼도 된다.

### 조건문과 반복문
```js
if (level === 0) {
  console.log("처음 시작합니다.");
} else {
  console.log("한 단계 성장했습니다.");
}

for (const skill of skills) {
  console.log(skill);   // 배열을 하나씩 꺼내서 실행
}
```
| 용어 | 쉬운 설명 |
|---|---|
| **조건문 (`if`/`else`)** | "만약 ~면 이거, 아니면 저거" |
| **반복문 (`for...of`)** | 목록의 항목을 하나씩 꺼내 같은 일을 반복 |
| **`===`** | 값과 **자료형까지** 같은지 비교. `==`는 자료형을 멋대로 바꿔서 비교하니 쓰지 않는다 (`1 == "1"`은 true, `1 === "1"`은 false) |

### 함수
```js
function makeGreeting(name) {        // name = 매개변수
  return `${name}님, 반갑습니다!`;   // return = 반환
}
const message = makeGreeting("광수"); // "광수" = 인수
```
| 용어 | 쉬운 설명 | 자판기 비유 |
|---|---|---|
| **함수** | 반복해서 쓸 동작에 이름을 붙인 코드 | 자판기 |
| **매개변수(parameter)** | 함수를 **만들 때** 정한 입력 칸 이름 | 동전 넣는 구멍 |
| **인수(argument)** | 함수를 **부를 때** 실제로 넣는 값 | 실제로 넣은 500원 |
| **호출** | 함수를 실행시키는 것 `makeGreeting(...)` | 버튼 누르기 |
| **반환(return)** | 결과를 함수 밖으로 내보내기 | 음료가 나옴 |

- 백틱(`` ` ``)으로 감싼 문자열 안에서 `${변수}`를 쓰면 값이 끼워진다 (**템플릿 리터럴**).
- **화살표 함수**는 같은 함수를 더 짧게 쓰는 문법이다. React에서 자주 본다.
```js
const makeGreeting = (name) => {
  return `${name}님, 반갑습니다!`;
};
```

### DOM과 이벤트 (가장 중요)
| 용어 | 쉬운 설명 |
|---|---|
| **DOM** (Document Object Model) | 브라우저가 HTML을 읽고 **JS가 만질 수 있는 형태(객체 나무 구조)로 정리한 것** |
| **이벤트(event)** | 브라우저에서 일어난 일 (클릭, 입력, 제출) |
| **이벤트 핸들러** | 이벤트가 일어났을 때 실행할 함수 |
| `document.querySelector("#id")` | CSS 선택자 문법으로 요소를 **찾기** |
| `addEventListener("click", 함수)` | "클릭되면 이 함수 실행해" 하고 **등록하기** |
| `textContent` | 요소의 글자를 읽거나 **바꾸기** |

> 비유: HTML이 **설계도**라면 DOM은 설계도대로 **실제로 지어진 집**이다. JS는 설계도가 아니라 지어진 집의 벽지를 바꾼다. 그래서 JS로 글자를 바꿔도 `.html` 파일 내용은 그대로다.

```html
<p id="message">버튼을 눌러 주세요.</p>
<button id="greeting-button" type="button">인사하기</button>
```
```js
const message = document.querySelector("#message");               // 1. 찾기
const greetingButton = document.querySelector("#greeting-button");

greetingButton.addEventListener("click", function () {           // 2. 등록
  message.textContent = "웹 개발을 시작합니다!";                  // 3. 바꾸기
});
```

### 파일 나누기
코드가 길어지면 역할별로 파일을 나눈다.
```
week0
├── index.html   구조
├── style.css    표현
└── script.js    동작
```
```html
<head>
  <link rel="stylesheet" href="./style.css" />
  <script src="./script.js" defer></script>
</head>
```
- `<link>`: CSS 파일 연결
- `<script src>`: JS 파일 연결
- **`defer`**: "HTML을 끝까지 다 읽은 다음에 JS를 실행해"라는 뜻이다. 이게 없으면 JS가 먼저 실행돼서 아직 안 만들어진 버튼을 찾다가 `null`이 나오고 오류가 난다.

## 5. 개발 도구: 에디터, 개발자 도구, 터미널

### 에디터와 확장 프로그램
| 용어 | 쉬운 설명 |
|---|---|
| **코드 에디터** | 코드를 쓰고 저장하는 프로그램 (VS Code) |
| **확장 프로그램(extension)** | 에디터에 기능을 더하는 플러그인. 스마트폰 앱 같은 것 |
| **Live Server** | HTML을 브라우저로 열고, 저장할 때마다 자동 새로고침해주는 확장. 오른쪽 아래 **Go Live** |
| `localhost` / `127.0.0.1` | "내 컴퓨터 자신"을 가리키는 주소 |
| **포트** (`:5500`) | 한 컴퓨터 안에서 프로그램을 구분하는 번호. 건물 안 호수 |

### 브라우저 개발자 도구 (DevTools)
`F12` 또는 `Ctrl + Shift + I`로 연다.

| 탭 | 확인하는 것 | 언제 쓰나 |
|---|---|---|
| **Elements** | DOM 구조 | 태그가 제대로 들어갔나? |
| **Styles** | 선택한 요소에 적용된 CSS. 취소선 = 다른 규칙에 덮어씌워짐 | 왜 색이 안 바뀌지? |
| **Console** | `console.log()` 출력과 **오류 메시지 + 줄 번호** | 왜 버튼이 안 눌리지? |

> `console.log(값)`은 화면이 아니라 Console에 값을 찍는다. "지금 이 변수에 뭐가 들었지?" 확인용이다.

### 터미널
| 용어 | 쉬운 설명 |
|---|---|
| **터미널** | 글자로 명령을 입력하는 창 |
| **셸(shell)** | 입력한 명령을 해석해서 운영체제에 전달하는 프로그램 (Windows는 PowerShell) |
| **CLI** | 글자 명령으로 쓰는 방식 (Command Line Interface) |
| **GUI** | 창·아이콘·버튼을 클릭해서 쓰는 방식 (Graphical User Interface) |
| **PATH** | 운영체제가 `node`, `pnpm` 같은 프로그램을 찾아보는 **폴더 목록**. 설치 직후 명령을 못 찾으면 터미널을 새로 열어야 반영됨 |

| 하려는 일 | 명령 (PowerShell) |
|---|---|
| 지금 위치 확인 | `pwd` |
| 파일 목록 보기 | `ls` 또는 `dir` |
| 폴더 이동 | `cd 폴더명` |
| 위 폴더로 | `cd ..` |
| 화면 지우기 | `cls` |

> 명령이 이상하게 동작하면 **`pwd`로 지금 어디 있는지부터** 확인한다. 엉뚱한 폴더에서 설치 명령을 치면 엉뚱한 곳에 설치된다.

## 6. Node.js와 패키지 매니저

### Node.js
| 용어 | 쉬운 설명 |
|---|---|
| **런타임(runtime)** | 프로그램이 실제로 **실행되는 환경** |
| **Node.js** | 브라우저 **밖**(내 컴퓨터, 서버)에서 JS를 실행하는 런타임 |
| **LTS** (Long-Term Support) | 오래 보안 수정을 해주는 안정 버전. 새로 깔 땐 LTS |

| | 브라우저 JS | Node.js |
|---|---|---|
| 실행 장소 | Chrome, Edge | 터미널, 서버 |
| 하는 일 | 화면, 클릭 처리 | **개발 도구 실행** (설치, 검사, 빌드) |

> 비유: JS는 언어, 브라우저와 Node.js는 그 언어로 일하는 **작업장**이다. 같은 요리사(JS)가 식당 주방(브라우저)에서도, 공장(Node.js)에서도 일한다.

프론트엔드에서 Node.js는 서버를 만들려고 쓰기보다 **개발 도구를 돌리는 엔진**으로 먼저 쓴다.

### 패키지와 패키지 매니저
| 용어 | 쉬운 설명 | 비유 |
|---|---|---|
| **패키지** | 다른 개발자가 만들어 공개한 재사용 코드나 도구 | 앱 |
| **패키지 매니저** | 패키지를 내려받고, 버전을 기록하고, 명령을 실행해주는 도구 | 앱스토어 |
| **npm** | Node.js 설치 시 같이 오는 기본 패키지 매니저 | 기본 앱스토어 |
| **pnpm** | npm과 같은 역할. 같은 패키지를 한 번만 저장해서 디스크를 아낌. **이 워크북의 기본** | 더 효율적인 앱스토어 |
| **`package.json`** | 프로젝트 이름, 쓰는 패키지 목록, 실행 명령을 적은 파일 | 장보기 목록 |
| **lockfile** (`pnpm-lock.yaml`) | 실제로 설치된 **정확한 버전**을 고정한 파일. 팀원 모두 같은 버전을 깔게 해줌 | 영수증 |
| **`node_modules`** | 설치된 패키지 실제 파일이 모이는 폴더. 용량이 커서 git에 안 올림 | 장 본 물건이 쌓인 창고 |
| **의존성(dependency)** | 프로젝트가 **실행될 때** 필요한 패키지 | 요리 재료 |
| **개발 의존성(devDependency)** | **개발할 때만** 필요한 패키지 (`-D`) | 요리 도구 |
| **스크립트(scripts)** | `package.json`에 이름 붙여 저장한 명령 | 단축키 |

### 명령어 비교
| 하려는 일 | npm | pnpm |
|---|---|---|
| 목록대로 전부 설치 | `npm install` | `pnpm install` |
| 패키지 추가 | `npm install 이름` | `pnpm add 이름` |
| 개발용 추가 | `npm install -D 이름` | `pnpm add -D 이름` |
| 제거 | `npm uninstall 이름` | `pnpm remove 이름` |
| 스크립트 실행 | `npm run dev` | `pnpm dev` |
| 패키지 명령 바로 실행 | `npx 이름` | `pnpm dlx 이름` |

> 한 프로젝트에 `package-lock.json`(npm)과 `pnpm-lock.yaml`(pnpm)을 **같이 만들지 않는다**. 영수증이 두 장이면 어느 게 맞는지 헷갈린다.

### 버전 확인
```powershell
node -v   # v22.12.0 이상이면 OK
npm -v
pnpm -v
```

## 7. 자주 하는 실수
| 증상 | 원인 | 확인 방법 |
|---|---|---|
| 버튼을 눌러도 반응 없음, Console에 `Cannot read properties of null` | `querySelector`가 요소를 못 찾음. id 오타(`#startButton` vs `start-button`)이거나 `defer` 빠짐 | HTML의 id와 JS 선택자를 글자 하나씩 비교 |
| 요소가 생각보다 큼 | padding·border가 width에 더해짐 | Styles 탭에서 박스 모델 그림 보기, `box-sizing: border-box` |
| CSS를 썼는데 적용 안 됨 | 더 센 선택자가 덮어씀 | Styles 탭에서 취소선 그어진 속성 찾기 |
| 한글이 깨짐 | `<meta charset="UTF-8">` 빠짐 | `<head>` 확인 |
| `pnpm`을 찾을 수 없음 | PATH가 아직 반영 안 됨 | 터미널 완전히 닫고 새로 열기 |
| Go Live 버튼이 안 보임 | 파일만 열고 폴더를 안 엶 | VS Code에서 File → Open Folder |

## 8. 스스로 점검하기
1. HTML, CSS, JS의 역할을 각각 한 단어로 말해보자.
2. `<div>`와 `<section>`의 차이는? `<div>`는 틀린 태그인가?
3. `width: 300px; padding: 20px; border: 1px solid;`인 상자의 실제 가로 길이는? `box-sizing: border-box`가 있을 때는?
4. 같은 모양 카드 5개를 꾸밀 때 class와 id 중 뭘 쓸까? 왜?
5. `justify-content`와 `align-items`는 각각 어느 방향을 정렬하나?
6. `const`로 만든 배열에 `push`가 되는 이유는?
7. 매개변수와 인수의 차이는?
8. JS로 `textContent`를 바꾸면 `index.html` 파일 내용도 바뀔까? (힌트: DOM)
9. `<script>`에 `defer`가 없으면 무슨 일이 생길 수 있나?
10. Node.js가 프론트엔드 개발에 필요한 이유는? 서버를 만들려고?
11. `pnpm-lock.yaml`은 왜 필요할까?

<details>
<summary>정답 보기</summary>

1. 구조 / 표현 / 동작
2. `<section>`은 "한 주제의 구역"이라는 의미가 있고, `<div>`는 의미 없는 상자다. `<div>`는 틀린 게 아니라 맞는 시맨틱 태그가 없을 때 쓴다.
3. 없을 때 300 + 20×2 + 1×2 = **342px**, 있을 때 **300px**
4. **class**. id는 페이지에 하나만 있어야 하고, class는 여러 요소가 공유할 수 있다.
5. `justify-content`는 주축(기본 가로), `align-items`는 교차축(기본 세로)
6. `const`는 변수가 가리키는 **참조**를 못 바꾸게 할 뿐이고 안의 내용은 수정할 수 있다.
7. 매개변수는 함수를 만들 때 정한 입력 칸 이름, 인수는 부를 때 실제로 넣는 값
8. 안 바뀐다. JS는 브라우저 메모리 속 DOM을 바꾸고, 새로고침하면 원래대로 돌아온다.
9. HTML을 다 읽기 전에 JS가 실행돼서 아직 없는 요소를 찾다가 `null` 오류가 난다.
10. 서버보다는 패키지 설치, 빌드, 개발 서버 같은 **개발 도구를 실행**하려고
11. 실제 설치된 정확한 버전을 고정해서, 다른 컴퓨터에서도 같은 버전으로 설치되게 한다.
